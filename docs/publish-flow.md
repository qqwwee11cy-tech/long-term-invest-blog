# 자동 글쓰기와 게시 절차

예약된 자동 글쓰기는 이 절차를 따릅니다. **블로그 주인(긍정글귀)의 결정(2026-10-21): 승인 메일을 보내지 않고, Claude가 스스로 점검해 기준을 통과하면 바로 게시합니다.** 승인을 기다리지 않습니다.

1. `docs/writing-guide.md` 전체와 해당 카테고리 절을 읽고, 해당 주제 목록에서 체크되지 않은 첫 주제를 고릅니다 (주간 시장 정리는 목록 없음).
2. 웹 검색으로 사실을 확인하며 글과 SVG 그림을 만듭니다. 주제 목록에서 그 주제를 `[x]`로 바꿉니다.
3. 점검: `docs/writing-guide.md` 맨 위 "블로그 주인의 글쓰기 규칙" 1~8번을 하나씩 확인하고 어긋난 곳을 고칩니다(규칙 9·10). 그다음 글 속 숫자를 출처와 다시 대조, 그래프 숫자와 본문 일치, 매수/매도 권유·목표주가·전망 표현 없음, 문장 베끼기 없음, frontmatter 확인, `npm install && npm run build` 통과, 가능하면 Playwright(executablePath `/opt/pw-browsers/chromium`)로 390px 너비 스크린샷 확인.
4. 새 브랜치 `post/<파일명>`으로 커밋·푸시하고 main 대상 PR을 엽니다. 브랜치 이름은 짧게(`post/<짧은이름>`) 짓습니다. PR의 Vercel 빌드가 Ready인지 확인합니다(실패하면 고쳐서 다시 푸시).

5. 게시 판단: 3단계 점검을 모두 통과했고 빌드가 Ready면 PR을 squash 머지해 게시합니다. 점검을 통과하지 못하면(숫자를 확인할 수 없음, 규칙을 맞출 수 없음 등) 고쳐서 다시 점검하고, 끝내 못 맞추면 게시하지 않고 PR을 닫은 뒤 주제 목록의 `[x]`를 되돌리고 다음 주제로 넘어갑니다.
6. 알림: 메일은 보내지 않습니다. 이 스레드에 게시한 글 제목과 링크(`https://long-term-invest-blog.vercel.app/posts/<파일명>/`)를 한 줄로 남깁니다. 게시하지 못했으면 그 이유를 한 줄로 남깁니다.
7. 주인이 스레드에서 게시된 글의 수정이나 내리기를 요청하면 그대로 반영합니다(수정은 새 PR로 고쳐 머지, 내리기는 글 파일 삭제).
