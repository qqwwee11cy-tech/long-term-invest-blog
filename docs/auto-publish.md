# 자동 게시 절차

예약된 자동 글쓰기는 이 절차를 따릅니다. 블로그 주인(긍정글귀)의 요청에 따라 **승인 없이 바로 게시**합니다. 그래서 게시 전 자체 점검을 꼼꼼히 합니다.

1. `docs/writing-guide.md` 전체와 해당 카테고리 절을 읽고, 해당 주제 목록에서 체크되지 않은 첫 주제를 고릅니다 (주간 시장 정리는 목록 없음).
2. 웹 검색으로 사실을 확인하며 글과 SVG 그림을 만듭니다. 주제 목록에서 그 주제를 `[x]`로 바꿉니다.
3. **게시 전 점검** (하나라도 통과하지 못하면 고치고, 고칠 수 없으면 그 부분을 빼거나 게시하지 않습니다)
   - 글 속 모든 숫자를 출처와 다시 대조했는가. 그래프 숫자가 본문·표와 같은가.
   - 매수/매도 권유, 목표주가, 주가 전망 표현이 없는가.
   - 기사·자료 문장을 그대로 옮긴 부분이 없는가.
   - frontmatter(title, description, pubDate=오늘, category, tags)가 맞는가.
   - `npm install && npm run build`가 통과하는가.
   - 가능하면 Playwright(executablePath `/opt/pw-browsers/chromium`)로 390px 너비에서 글 페이지를 찍어 그림 글자가 읽히는지 확인.
4. main에 직접 커밋하고 푸시합니다 (커밋 메시지: `Add post: <제목>`). 푸시하면 Vercel이 1~2분 안에 사이트에 반영합니다.
5. 게시 알림
   - Gmail 도구(`mcp__Gmail__send_message`, ToolSearch로 불러오기)가 있으면 `qqwwee11.cy@gmail.com`으로 메일을 보냅니다. 제목 `[천천히 부자되기] 새 글 게시: 「제목」`. htmlBody는 흰 배경, 강조색 #1f7a4d, 최대 너비 520px 카드: 제목, 요약 2~3문장, 초록 버튼 "글 보러 가기"(https://long-term-invest-blog.vercel.app/posts/<파일명>/), 작은 안내 "고치거나 내리고 싶으면 Claude 프로젝트 대화에 말씀해 주세요." body에는 같은 내용을 일반 텍스트로.
   - 이 스레드에도 reply로 제목, 요약, 글 링크를 보내고 "고치거나 내리고 싶으면 여기에 말씀해 주세요"라고 덧붙입니다. 메일을 못 보냈으면 그 사실도 한 줄 적습니다.
6. 블로그 주인이 수정을 요청하면 main에 반영해 다시 게시하고, 내려 달라고 하면 그 글 파일을 지우거나 `draft: true`로 바꿔 푸시합니다.
7. 점검을 통과하지 못해 게시하지 않았으면, 그 이유를 스레드에 알리고 메일도 보냅니다.
